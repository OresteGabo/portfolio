# Security audit — 30 October 2026

Scope: the current KMP working tree and companion `gabo-portfolio-api` Spring working tree, including pending performance/UI/planning changes. This is a source audit with synthetic local tests and public advisory checks, not a production penetration test, certification or legal-compliance opinion. Existing work was preserved. No production database, credentials, PDFs, cloud logs or infrastructure configuration were accessed or changed.

## Verified findings and fixes

| ID / priority | Evidence before change | Implemented protection / verification |
|---|---|---|
| SEC-01 / High — private-derived prices exposed through public history | `MarketHistory.tradeHistory` selected contract-backed equity purchases across all owners. `GET /rse/equity-history` is public. Even without names/quantities, private dates, prices and low/high ranges leaked outside their accounts. A new two-account integration test failed against the original code | `MarketController` supplies only the authenticated principal's account ID. `MarketHistory` filters contract rows by that ID; anonymous calls skip private queries and return official exchange observations only, with `tradeHistoryAvailable=false`. Same response shape. Test proves public absence, caller-only prices/ranges and no contamination by the second account |
| SEC-02 / High — untrusted shared issuance publication | Any invited account could label a PDF `Bond issuance`, supply canonical terms and trigger `pending.refresh()` across accounts. Source metadata was client supplied. A new test showed an invited user's upload could publish shared content and change another account's pending terms | Publication now requires the existing owner identity in `DocumentService`, before staging any parts. Invited personal allocation/contract/statement uploads remain private and supported. Approved shared reports remain readable by signed-in users. Existing owner publication, duplicate/conflict, multipart and two-session tests pass; the invited publication test now returns 403 with no staged row, canonical document or changed pending terms. Mobile review explains the restriction |
| SEC-03 / High integrity — partial scheduled receipt updates | `LifecycleNotifications.daily` called its own `@Transactional sync`, bypassing Spring's proxy. Transaction-scoped advisory locks and earlier automatic coupon writes could complete outside the intended transaction. A synthetic PostgreSQL trigger forced a later notification failure; the original code left a coupon acknowledgement committed | Existing `TransactionTemplate` infrastructure now establishes a real transaction per account before `sync`. The regression proves complete rollback on failure, then one receipt after repeated successful runs. No ledger, cron system or enterprise transaction framework added |
| SEC-04 / Medium — truncated/unsupported PDF envelopes accepted for storage | Completed uploads originally checked only length and a `%PDF-` prefix. This did not establish a supported version or complete trailer | Added bounded PDF 1.0–1.7/2.0 header and terminal `%%EOF` checks, preserving the existing 10 MiB limit, canonical base64/chunk bounds and atomic upload transaction. Regression rejects truncated data without visible documents or a retained single-chunk row; unit tests cover unsupported versions, trailing payloads, whitespace and size. **Envelope validation is not a full PDF parser, antivirus scan or signature validation** |
| SEC-05 / Component hygiene — dependency advisory matches | Public OSV batch queries against 488 unique selected Maven/npm coordinates returned nine advisory IDs on four backend coordinates. A version match alone does not establish a reachable exploit | Upgraded Guava 33.6.0-jre → 33.7.2-jre, jsoup 1.21.2 → 1.23.2, Bouncy Castle 1.83 → 1.85.2, and the Spring-managed stable OpenTelemetry family 1.62.0 → 1.67.0. Verified resolved versions and full backend tests. Repeat scan: 493 unique coordinates, zero returned advisory matches. See DEPENDENCIES.md for sources and reachability limits |
| SEC-06 / Medium — anonymous expensive refresh bypass | Public `refresh=1` bypassed the market service cache and could repeatedly trigger fixed-host upstream fetches. A synthetic-upstream integration test failed before the change | Anonymous requests now follow the normal cache policy even when a refresh parameter is supplied. Authenticated app refresh and separately authorized scheduler paths remain available. Test proves no extra upstream reads for anonymous quote/market refresh, and a signed-in refresh still performs a fresh read. This is not a complete denial-of-service or per-account quota system |

All three initial application regressions were executed against the unmodified implementations and failed their security assertions. They pass after the corresponding fixes. Existing ordinary purchase/document isolation was not misrepresented as entirely broken: the demonstrated disclosure was the separate contract-derived chart projection, and the demonstrated cross-account write was shared issuance publication.

### Files and compatibility

Backend changes: `MarketHistory.kt`, `MarketController.kt`, `DocumentService.kt`, new `PdfUploadPolicy.kt`, `LifecycleNotifications.kt`, dependency versions/constraint in `build.gradle.kts`; guarded anonymous cache bypass; HTTP integration regressions and new `PdfUploadPolicyTests.kt`. Previous authentication/performance changes in other modified files belong to the preceding task and were retained.

Mobile changes: owner-publication explanation/guard in `ConversationReview.kt` and legacy `BondIssuance.kt`, accurate private-chart copy in `PlanningScreens.kt` and `FrenchStrings.kt`, legal source `docs/legal/content.json`, generated legal Kotlin/Markdown and updated privacy-copy regression. Current and older clients receive the same JSON shapes; invited clients attempting a new shared publication now correctly receive 403. Owner review is a trust boundary, not a guarantee that a PDF is public, authentic or malware-free.

No schema migration or data deletion is required. No existing PDFs or saved investments were rewritten. This also means pre-existing shared issuance rows and already disclosed/cached data are **not repaired retroactively**. The shared table lacks reliable uploader provenance for every older row. Before rollout, the operator must review existing canonical reports and affected pending terms against genuine public issuer evidence. Do not assume a new owner-only gate proves every old shared file was public. Do not delete or change investors' historical evidence on a guess.

Deploy the backend privacy/authorization fixes before or together with the updated app/privacy content. Generated notice updates describe the changed implementation, not a verified production rollout. Review any proxy caches and the actual formerly deployed versions before concluding whether an incident occurred; this audit found vulnerable source paths, not evidence of a production breach.

## Controls already implemented correctly

| Area | Verified source-level safeguards and limits |
|---|---|
| Authentication | `AuthService`: random opaque twelve-hour cookies; database stores token hashes, not plaintext tokens; expiry, disabled-account and credential-version checks; supported PBKDF2/scrypt verification; account/IP/global attempt limits; invitation-only registration with high-entropy, expiring, single-use tokens. Session results are not cached across requests. No MFA/recovery claim |
| Authorization / isolation | Controllers derive account context from Spring Security, not body `owner_id`. Ordinary purchases, equities, documents, statement evidence/decisions, receipts and notifications bind owner parameters. Owner-only administration is a deliberate privileged function, including account summaries; it is not access granted to invited users. Existing tests cover another account's read/write/PDF/proof/statement decisions returning 403/404 and ignored injected owner fields |
| API boundaries | HTTPS-only production client origins; no credential-forwarding redirects; strict configured CORS and mutation Origin plus JSON checks; secure HttpOnly SameSite cookies in production; private/no-store responses, generic failures and download attachment/nosniff. Release Android does not inherit debug cleartext configuration. iOS ATS permits local networking, not arbitrary remote HTTP. Actual ingress/TLS/proxy settings were not inspected |
| Document uploads | Authenticated/account-scoped staging; 512 KiB chunks, canonical base64, 1–20 parts and at most 10 MiB complete content; bounded HTTP JSON bodies; eight unfinished uploads per account; immutable part metadata; same-part retry checks; account/hash deduplication; completed uploads atomic. Private categories cannot publish shared rows. New publication and envelope boundaries are server enforced, not UI trust |
| PDF processing | On-device import limits: 10 MiB, ten pages, five OCR pages, 200,000 text characters and bounded image/canvas allocation. PDF.js importer rejects document actions, embedded files, active forms/annotations while permitting passive signature widgets; XFA is disabled. iOS PDFKit/Vision uses analogous active-content checks. Native viewer rasterizes pages with allocation caps rather than executing document scripts. Signature-widget acceptance is not cryptographic signature verification. Complex native parsing still depends on patched OS/engine code |
| Native credentials / encryption | Android Keystore authentication-bound wrapping key plus AES-GCM, transient data key cleared on lock; iOS passcode-bound ThisDeviceOnly Keychain user-presence ACL/LAContext invalidation. Cookie snapshots and saved credentials persist only through these vaults. Biometrics are OS-local, not server authentication or raw biometric collection. No new auth store or encryption scheme added |
| Local state | Private portfolio/PDF bytes are cleared from the model on lock/logout; background grace checked monotonically on resume. Android application backup is disabled. Import journal is account scoped and excludes PDF bytes, extracted financial amounts and credentials. Filenames, IDs/digests, timestamps/counts and monthly target preferences remain local metadata; iOS defaults/backup scope still needs inventory. Sandbox storage is not a promise against rooted/jailbroken devices or all OS backup access |
| Temporary documents | Android FileProvider is unexported and exposes only the private `pdf-share/` cache subtree through temporary read grants; names are sanitized. Share cache cleanup is opportunistic after 24 hours on a later share, not a timed erasure guarantee. Renderer files are deleted on close/failed initialization and stale preview files on later initialization. iOS uses unique temporary directories and `finally` cleanup after share/export completion/cancellation. Crash leftovers/OS protection and recipient copies require separate retention/device review |
| Database / financial integrity | Bound JDBC parameters, whitelisted fields/statuses, server-side canonical amounts, database constraints/uniqueness, transaction/account locks, account-ownership proof checks. Statement imports create evidence/reminders, not new holdings for arbitrary cash rows; uncertain matches require explicit reasons, revision checks and correction history. General bond edits still lack a complete immutable audit/version contract; that remains ordinary-product debt, not deferred certification work |
| Logging / errors | Application errors expose approved/generic messages, not SQL/stack/PDF/password contents. Import diagnostics use allowlisted codes. Optional timing logs contain fixed route/stage labels, durations and bounded correlation IDs, not payloads/cookies. Push messages omit balances/quantities/account identity. This does not verify proxy, provider or operator-enabled debug logging. SQL TRACE and request/body/header logging must remain off for real data |
| Account deletion | Eligible invited account deletion reauthenticates with a password, serializes with account mutations, removes active account-linked records/PDFs/evidence/devices/sessions and uses cascade cleanup for dependent delivery rows. Stale authorized writers are rejected after deletion. Environment-managed owner/friend accounts follow an explicit separate path. Provider backups, exported copies and already shared public rows are not automatically erased; never promise otherwise |
| Export | Existing account-scoped full-history exports warn that readable financial figures and an attached JSON archive can leave the app even when number hiding is enabled. Original PDFs are not embedded. Native explicit sharing/save is retained; exported/recipient copies are outside subsequent app erasure. No credentials/cookies in the report model |
| Backup/recovery | Migration documentation calls for backups, restored-copy validation and controlled cutover. No live backup schedule, encryption/KMS, retention, restore exercise, RPO/RTO, deletion-on-restore process or region evidence was supplied. These are **unverified**, not implemented by having PostgreSQL/Flyway |

## Tests and evidence

All backend changes ran through a fresh disposable loopback PostgreSQL 18 database, Flyway V1–V8 and real Spring HTTP/security tests; no production connection. The initial three failing-before regressions are named:

- `private contract prices remain account scoped and absent from public history`
- `only the owner can publish shared issuance and change other accounts pending terms`
- `daily lifecycle sync rolls back coupon acknowledgements when notification work fails`

An additional `anonymous refresh parameters cannot repeatedly bypass the market cache` regression also failed before the refresh fix. The completed suite has **48 backend tests**, zero failures, and `bootJar` passes. It includes existing opaque-session expiry/revocation, cross-account purchases/documents, injected ownership, malicious references, upload/retry limits, deletion and statement correction/isolation regressions, plus envelope tests. Android shared tests and iOS results are in the final VERIFICATION.md entry. Native PDF security fixtures exist; no new parser/service was invented for the audit.

The dependency scan covered selected Android runtime and Spring runtime Maven graph coordinates, the backend's locked npm tooling and identified vendored PDF/OCR versions. It did not send source code, secrets, repository-private names or financial files to OSV. The inspected vendored PDF.js is 6.4.299 and byte-matches the installed source copied into the app; Tesseract.js/core are 7.0.0. OS/native libraries, devices, cloud images, build tools and unknown advisories require their own update/assessment process. A clean query result is not certification.

## Remaining work before wider production use

1. Review existing shared issuance files/terms and coordinate backend/mobile/privacy rollout; assess any prior deployment exposure using real evidence. Do not declare a breach or absence of one from these local tests.
2. Verify TLS to PostgreSQL, cloud IAM/service-account privileges, secret rotation/access, provider regions and subprocessors. Database PDF content is base64 encoding, **not application encryption**; provider encryption-at-rest/backups were not verified.
3. Define and operate backup/restore and retention policies in OPERATIONS.md. Incomplete upload cleanup currently occurs on later uploads for the same owner; it is not an independently scheduled purge. Completed storage has no per-account lifetime quota. Choose operational limits from measured volume before opening registration more broadly.
4. General financial mutation audit and stale-edit/version checks remain P1 data-integrity work. Reconciliation-specific correction history does not solve every bond edit/delete or reconstruct all year-end states.
5. Verify physical-device lock/capture/biometrics, iOS backup exclusion/protection for local metadata, crash-leftover cleanup and OS security updates. No new claim of root/jailbreak resistance.
6. Obtain legal review of the questions in RWANDA_DATA_PROTECTION.md and correct actual legal-entity, provider/region, retention and rights-contact facts before publishing legal notices. Technical safeguards alone do not establish legal compliance.
7. Confirm configured Firebase/APNs delivery and credentials after dependency updates. Automated tests do not send real notifications or validate those providers. Keep dependency/advisory review recurring and pin/verify resolved builds; this pass was a one-time snapshot.

## Deliberately deferred

Institutional compliance frameworks, enterprise audit attestations, formal certifications, continuous external penetration-testing programs, organization/tenant RBAC and broker-specific regulatory controls need actual customers, data flows and legal requirements. They are documented future work, not substitutes for the current account boundaries. No auth replacement, microservices, RLS rewrite, paid malware/OCR service, SIEM or enterprise key-management platform was introduced. Plan a bounded independent penetration test before material public/institutional expansion, with explicit authorized targets and synthetic/staging data.
