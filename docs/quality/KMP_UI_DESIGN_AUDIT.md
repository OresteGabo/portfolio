# INZIRA KMP UI design audit

> Historical scoped audit. Its original exclusions, failures and Git disposition below describe the earlier isolated attempt. The 15 November combined integration and current disposition are recorded in [KMP_PENDING_CHANGES_REVIEW.md](KMP_PENDING_CHANGES_REVIEW.md); that later review supersedes the status here without reclassifying a failed historical run as passed.

Date: 2026-11-15. Baseline: `f7ef53f`, branch `main`.

## Scope and evidence

This review covers the mobile UI, shared Compose components, native presentation surfaces, resources, and UI tests. No backend, website, API, persistence schema, portfolio formula, import parser, or authentication policy is changed. The existing pending notification-test permission setup correction is included solely to make the UI regression gate deterministic; other pending work is excluded. Existing unrelated working-tree changes are excluded from this UI patch and its isolated verification export. Source review is broader than runtime visual verification; the matrix below identifies what was actually rendered.

The baseline contains 83 commonMain Kotlin files with `@Composable`. The source inventory at the end includes entry screens and supporting components; a composable file is not necessarily a screen. Large drawing/animation files are intentional artwork rather than evidence that every literal coordinate needs a token.

| Concern | Repository evidence |

## Findings and disposition

Paths below are relative to `app/shared/src/commonMain/kotlin/dev/orestegabo/portfolio/` unless stated otherwise. Severity describes UI/maintenance impact, not financial correctness.

| ID / severity | Evidence and consequence | Change / next step |
|---|---|---|
| UI01 Medium — incomplete surface roles | `design/StructTheme.kt` previously set basic surface/background but inherited Material's remaining container, variant, tint, background-content and outline roles. Default Material containers/field outlines did not follow the warm Inzira palette. `StatementScreens.MissingStatementTile` uses `surfaceVariant`; dashboard, detail and purchase cards use `outlineVariant`; Material dialogs/fields use additional roles. | **Changed:** explicitly derive neutral surface/container/outline roles from existing ink/canvas/night colors, assign background-content and secondary-content pairs. Preserve olive/cream primary roles. Added contrast tests across both themes. Error/tertiary/inverse roles retain Material defaults; no new arbitrary semantic colors. |
| UI02 Medium — repeated modal progress layout | `PdfImportProgressDialog` used a 32 dp spinner; `PortfolioReportProgressDialog` used 28 dp; `LoadingState` used 26 dp/2 dp stroke. Both modal progress bodies independently laid out text and indicators. | **Changed:** `ProgressContent` owns the weighted text column, 28 dp/3 dp indicator and merged polite indeterminate progress semantics. Dialog text is vertically scrollable. Admission, cancel actions, safe PDF detail filtering and report state remain in callers. No claim that a pre-existing overflow was reproduced. |
| UI03 Medium — unbounded forms | `ShareOrderScreen`, `EncryptedBackupScreen`, `PdfImportPreparationScreen` filled available width. This is inconsistent with the existing 480 dp sign-in, 460 dp unlock and 600 dp onboarding width caps; tablet fields/actions could span the whole display. | **Changed:** shared `FormContent` centers a maximum 600 dp content region without owning padding, scroll, keyboard, navigation or data. All three retain their scrolling and actions; backup now explicitly uses IME padding. Other editor screens remain candidates for a subsequent measured pass. |
| UI04 Low — inconsistent primary empty/backup actions | `EmptyState` used a 50 dp minimum/16 dp radius, versus the existing pending-share/unlock pattern of 56 dp/18 dp. Backup actions had only Material defaults. | **Changed:** empty-state primary action uses 56 dp minimum/18 dp shape; backup actions get 56 dp minimum. `heightIn` allows large text to grow. Compact text/secondary actions are intentionally not inflated to primary action dimensions. |
| UI05 Medium — dimensional vocabulary scattered | Shared cards/actions repeatedly spell 24/28 dp shapes, 20 dp inline icons and common 4–32 dp spacing. Other similar sizes are artwork-specific. | **Changed incrementally:** `InziraSpacing`, `InziraShapes`, `InziraDimensions`; adopted by empty/loading states and touched forms. Do not mechanically replace chart radii, path coordinates, circular badges or text baselines. Existing `Panel` and legacy editors still spell equivalent literals; migrate when independently edited. |
| UI06 Medium — tablet navigation/content policy absent | `InvestmentApp` always renders five bottom destinations. Dashboard uses constrained/horizontally scrollable insight cards; details have local width/font breakpoints. No list-detail or rail policy exists for the app as a whole. | **Open:** define a tablet product layout before changing navigation. Use window constraints, not physical device identity. A new navigation dependency is not justified for this focused patch. No claim of tablet-wide redesign. |
| UI07 Medium — dense calendar/header rows | `CalendarScreen` month header, three-category legend and event/action rows remain horizontal; `SubscriptionTodayCard` has several concurrent labels/actions. `Fact` uses two equal-width columns while `DetailValueRow` already stacks at narrow widths/large text. | **Open:** add calendar/header/legacy `Fact` large-text fixtures before changing wrapping. Static source evidence establishes constrained rows, not a reproduced clipping defect. Do not turn every financial row into an unrelated visual style. |
| UI08 Medium — older editors differ | `PurchaseForms`/`PurchaseImportScreens`/`YearlyCouponsScreen` use 52 dp actions; sign-in contains 42/48 dp minima, while unlock/share order use 56 dp. Material touch-target enforcement and visual height are different concerns. | **Open:** classify primary, secondary, compact and destructive actions before migrating. Do not make every button identical. Share-order callbacks/edit/save rules remain untouched. |
| UI09 Low — card and elevation differences | `Panel` has 24 dp corners/1 dp tonal elevation; pending/purchase/import cards also use 16/18/20/22/24 dp shapes, the hero has a deliberate fade, import messages use asymmetric corners. | **Partly addressed:** tokenized shared empty/order shapes; retained hierarchy/artwork/message shapes. No universal elevated card wrapper or new shadow scale: flattening every container would remove established grouping. Future migration should distinguish content cards from notices and chat bubbles. |
| UI10 Low — icon/stroke policy | Shared actions use Material icons around 18/20/24 dp; import preparation uses 28 dp step icons and a larger PDF illustration. Brand vectors, calendar event dots and custom chart strokes are different roles. | **Partly addressed:** 20 dp inline icon token for touched shared components. No global stroke rewrite; Material glyphs and logo/path illustrations are not interchangeable. Audit perceived weight with actual screenshots before replacing icons. |
| UI11 Medium — native palette duplication | `app/iosApp/ShareImport/ShareViewController.swift` authors olive/cream and dynamic canvas; SwiftUI `NextWidget/WhatsNextWidget.swift` and `BondLiveActivity/BondLiveActivity.swift` author their own colors/fonts. The current color checker does not scan those extension directories. Android resources use generated named colors. | **Open:** extend generated native token coverage with extension-specific roles and tests in a separate native change. Keep widgets' explicitly fixed dark presentation and live-activity/system presentation intentional; do not silently change widgets when toggling the in-app theme. |
| UI12 Medium — limited visual regression gate | Android scenario tests cover onboarding, details, share order and PDF flow, but there is no configured Paparazzi/Roborazzi/golden screenshot task or Compose compiler metrics destination. Current Android app suite has a pre-existing native PDF-sharing crash. | **Added:** real Compose layout/accessibility tests plus opt-in synthetic captures. **Open:** establish reviewed screenshot baselines, add actual modal/IME/iPad cases, resolve existing full-suite failure. Passing source/contrast tests alone cannot establish visual equivalence. |
| UI14 Medium — root coordination still reaches infrastructure | `InvestmentApp` routes a document purchase by looking in `model.purchases` and falling back to `model.api.request("/api/bonds/purchases/$id")`. Several screen entry points receive the whole `PortfolioModel`. | **Open:** place route resolution behind an explicit model action and supply smaller presentation inputs when those features are independently changed. Do not introduce a second navigation framework or change fetch/error semantics as part of visual token work. The unrelated pending responsibility extractions are not counted as fixes in this patch. |
| UI13 Low — interaction states mostly inherited | Material controls provide enabled/disabled/selected/focused/pressed behavior. `Field` preserves secure masks/IME handling; `ChoiceRow` uses selectable/radio semantics. Some custom cards use clickables and tinted surfaces. | **Retained:** no hand-rolled universal interaction-state framework. New components add no business enabled-state decisions. Verify custom selected/disabled cards with TalkBack/VoiceOver before broader extraction. |

No hardcoded hexadecimal `Color(...)` was found outside the shared design package in the baseline composable inventory. Explicit typography sizes and dimensions exist, particularly in artwork; their presence alone is not a defect. Semantic gain/loss, calendar and warning/status roles already exist in `StructColors`; this patch does not invent tax/status colors or repurpose financial meaning.

## Component and token decisions

| Addition | Responsibility / consumers | Deliberately excluded |
|---|---|---|
| `design/InziraDimensions.kt` | Spacing 4, 8, 12, 16, 20, 24, 32 dp; action/card/spacious-card shapes 18/24/28 dp; inline icon 20 dp; progress 28 dp/3 dp; primary action minimum 56 dp; form maximum 600 dp. | No global file-length rule, artwork geometry scale, new typography family, animation timings or arbitrary elevation ladder. |
| `investments/ProgressContent.kt` | Label + optional supporting detail + decorative spinner; merged accessible progress. Used by PDF and portfolio-report progress dialogs. | No retries, cancellation decisions, parsing, exception mapping, financial data conversion or network activity. |
| `investments/FormContent.kt` | Center constrained content using existing Box/widthIn APIs; used by order, backup and PDF preparation. | No route, state holder, scroll container, system inset ownership or new platform target. |
| Existing `EmptyState` / `LoadingState` | Reuse the existing artwork/action API; adopt common sizes/spacing. | No duplicate generic error/success/card framework. Financial text continues through privacy-aware components. |

Error states continue to use Material error roles; primary/secondary actions use the existing olive/cream brand roles. Display values retain their existing financial formatting and masking. Default Material typography and control state behavior remain the source of truth. New components are UI helpers with no dependency on core/domain infrastructure.

## Before / after and responsive review

Before: surface-role defaults mixed with authored palette; three loader sizes; repeated modal bodies; three full-width forms. After: brand-derived neutral container roles, one modal progress body, shared progress dimensions, readable centered forms and explicit backup IME padding. This is a consistency patch, not a dashboard or brand redesign. No runtime performance improvement is claimed.

Already sound and retained:

- `OnboardingScreen` caps width at 600 dp, uses measured artwork, scrollable page content, short-window copy ordering and safe-drawing insets.
- `SignInScreen` caps at 480 dp and handles IME; `UnlockScreen` caps at 460 dp and scrolls.
- `DetailColumns` stacks below 300 dp or font scale 1.4; `DetailValueRow` below 280 dp or font scale 1.4. `DetailAmount` changes hierarchy at the same readability boundary.
- Root `Scaffold` supplies system-bar/navigation padding; PDF preparation independently owns safe-drawing padding. The new form wrapper adds no competing inset policy.
- Dashboard insight cards intentionally scroll horizontally rather than compressing financial information. PDF pages retain document aspect ratio/zoom and a dark reader canvas even in light mode.

Still requiring device/product validation: actual software-keyboard overlap on both platforms, system-bar/cutout combinations, iPad split view, foldable hinges, calendar large-text rows, native extension Dynamic Type and RTL. No foldable emulator or iPad visual run is claimed. Accessibility semantics do not substitute for a full assistive-technology review.
