## P2: financial interpretation and maintenance

- **Decimal boundary:** Native monetary calculations now use BigDecimal/NSDecimalNumber; ratios, wire/UI compatibility and hypothetical TypeScript estimates still use Double/Number; BigDecimal/NUMERIC cover important persisted fields but not every intermediate. Define currency precision, rate units, rounding stages and tolerances before replacing representations. Use typed BigDecimal request fields server-side and compatible canonical responses when that migration is undertaken. Never silently round historical records or rewrite existing dedup identities.
- **Versioned financial assumptions:** Treasury tax now respects supplied validated rates, with a 5% default only when absent; pending commission and projection rates/charges are also hardcoded defaults. These are observed software policies, not a finding that they are correct for every instrument/date. Verify and version applicable assumptions before expanding markets; do not retroactively recalculate saved trades from new defaults. New receipt and native monetary amounts use two-place HALF_UP; historical receipt rows were preserved. Applicability/versioning of defaults still needs explicit policy.
- **Receipt evidence:** `coupon_receipts` stores `received` plus manual/automatic method. Automatic due-date acknowledgement is not bank verification. Report wording already explains this; preserve that distinction in future totals. A statement-verified evidence state is a future data contract, not currently implemented.
- **Valuation scope:** Bonds are valued at principal, unquoted shares at cost; there is no full cash/FX/liability/dividend/realized-return system. `estimatedNetWorth` is a legacy name for a limited investment estimate. A matured active record is not evidence of cash redemption. Keep scope visible and avoid presenting cost fallback as an observed price.
- **Annual history:** Current records can be edited or sold after year end; client report reconstruction cannot replace dated immutable holdings/transaction snapshots. Implement durable events before promising audited historical performance or tax accuracy.
- **UTC vs Kigali dates:** `Today`/MobileOverview use UTC while subscription/lifecycle logic uses Kigali/GMT+2. Around midnight, goal and payment boundaries can differ. Choose explicit business dates per use case and add cross-runtime year/month boundary fixtures; do not change display/local dates indiscriminately.
- **Live canonicalization/read mutations:** Spring `bonds()` calls `pending.refresh`, and PurchaseValidation can fill catalog terms on reads. Read responses can enrich/mutate financial interpretations without a durable audit event. Separate enrichment commands from projections incrementally and retain source/version attribution.
- **Broker coupling:** BK Capital validation and matching are embedded in parser/backend statement services; JSON keys/warnings are stringly typed. Use the added parser port for new broker adapters, then typed proposals/validators, not conditional broker logic throughout the domain.
- **Signature meaning:** PDF policy permits appropriate signature widgets and blocks active content, but extraction is not cryptographic signature verification or broker authenticity verification. Do not label a parsed document as independently authenticated.
- **Missing original upload time/digest metadata:** Spring list currently omits created_at/sha256 despite storing them. Exact checks may download candidate PDFs; old cloud timestamps cannot be inferred from issue dates. An additive authorized metadata response can improve accuracy/cost without changing file bytes or IDs.
- **Data growth/query work:** Base64 PDFs inside PostgreSQL add storage/backup overhead. Compact overview reduces network payload but still computes from complete server records; account summaries and lifecycle sync can repeat full reads. Measure representative latency/query count/storage before adding caches, indexes, queues or object storage.
- **Reproducible parser build:** Scripts load TypeScript/package assets from a developer-specific sibling website path. Checked-in runtimes make current builds work, but regenerating them is not self-contained or pinned here. Add tool lock/version/source-hash provenance and generated-vs-source verification before a parser release pipeline change. Existing ESM-vs-bundle tests do not prove the TypeScript snapshot itself was freshly rebuilt.
- **Broad coordinator:** PortfolioModel combines session, imports, notifications, goals and reports. Extract application services by use case only as those areas change. Keep the UI state facade while moving orchestration behind small ports; avoid a wholesale rewrite.

## Security and production dependencies

- Custom session auth has useful safeguards (hashed opaque tokens, secure HttpOnly SameSite cookies, credential-version invalidation, owner-scoped SQL, bounded bodies, generic errors and rate limiting). It is not MFA, federation or an institutional authorization model. Keep the functioning auth provider; review proxy/origin/IP assumptions and recovery requirements before public expansion.
- owner_id isolation is application/SQL enforced, not a demonstrated organization/RLS model. Audit every new endpoint, job, report and document path, not just UI filters. Public issuance data must remain distinct from private personal confirmations.
- iOS screenshot shielding uses an undocumented secure text-canvas workaround. Android experimental capture behavior is debug-only and differs from release. [The store audit](STORE_READINESS_AUDIT.md) remains applicable evidence; physical-device/review acceptance was not revalidated here.
- The known Android notification permission lint error and API-24 settings fallback were fixed in the preceding audit's current working tree. Release lint still reports warnings; it is not equivalent to a signed store submission or provider delivery test.
- Push credentials, Apple associated-domain/distribution capabilities and website API-domain setup are deployment dependencies. Presence of an SDK/entitlement is not proof they are configured live.
- Cloud configuration documents Neon pooled queries and direct Flyway connections. Preserve PostgreSQL/Flyway; test schema changes on disposable PostgreSQL or an isolated branch. Connection strings, deployed migration version, storage bills, backup/PITR retention and restore success were not live-verified.
- Spring has JPA dependencies despite observed JDBC persistence. Treat removal as a measured follow-up with startup/integration tests, not an automatic dependency deletion.
- Mobile signing/versioning, privacy/retention policy facts and release-channel behavior still need operator decisions. Do not collect extra sensitive data to solve hypothetical future reporting needs.

## Existing mitigations: do not rebuild them

- Server owner-scoped financial operations, numeric validation, database uniqueness and transactions already exist. TD-02–TD-04 improve audit/concurrency/recovery semantics; they do not mean persistence lacks all protection.
- Document hashing, bounded uploads, parser policy, import review, duplicate detection and same-file retry already exist. TD-01 is a specific statement contract mismatch, not a need to write a new PDF subsystem.
- Fee-aware unrealized gains, per-currency valuations and annual/portfolio reports already exist. TD-10 describes missing accounting inputs for broader performance.
- The preceding audit added schedule guards/parser separation and fixed Android permission/API-24 settings issues. Those are implemented in the current working tree; this phase did not implement them again.

## Validation required before closing gaps

Use the existing tests rather than a replacement test stack. For backend changes, run the PostgreSQL/Testcontainers integration suite and add cases for the exact defect: statement upload, transaction boundaries, stale edits, response loss and account access. For schedules/precision, add cross-runtime golden fixtures before changing calculations. For native/platform claims, validate actual device/signed/provider behaviour.

The preceding audit's executed results are in [VERIFICATION.md](VERIFICATION.md); source-only risks, existing tests and executed tests are separate evidence. No production database, restore, broker grant, regulatory status or deployment was inspected here. Keep secrets and raw document content out of audit logs and fixtures.
