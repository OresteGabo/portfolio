## Reproduction and follow-up policy

1. Resolve current coordinates, including transitive dependencies and declared build plugins, with Gradle (do not scan only version catalogs); preserve configuration/scope. The audit used an isolated Gradle init task selecting releaseRuntimeClasspath, androidRuntimeClasspath, runtimeClasspath, jvmRuntimeClasspath and iosArm64CompileKlibraries where available, with configuration cache disabled for the inspection task. Use a temporary init script, not a production build change.
2. Read npm `package-lock.json` entries, retain exact version/dev attribution, and include vendored engine versions. Lockfile `dev: false` does not by itself establish runtime reachability.
3. To repeat this **snapshot's** OSV check, POST `{"queries":[{"package": entry.package,"version": entry.version}, ...]}` in batches of 100 from the saved inventory to [OSV querybatch](https://google.github.io/osv.dev/api/#tag/api/POST/v1/querybatch). Omit local `scopes` from the submitted payload. Require response count = query count and treat network/partial failures as NOT RUN. Fetch each returned advisory ID from `https://api.osv.dev/v1/vulns/{id}`. Refresh the inventory before a release; repeating a snapshot does not discover new dependencies.
4. In each website run `npm audit --json` and `npm explain glob minimatch deepmerge --json`. Do not use `npm audit fix --force` as an unreviewed fix.
5. After compatible dependency updates, repeat unit/HTTP/build/native gates, regenerate the advisory evidence and record remaining exceptions with an owner, rationale and expiry. No exception has been risk-accepted by the founder during this audit.
6. Add CI advisory checks that distinguish triaged exceptions from new high/critical findings. Before public beta, enable a reviewed secret scanner and produce/scan a container SBOM from the exact image digest. Tools for those two gates were not installed/run here.

Source feeds checked 31 October 2026. Feed mistakes, incomplete ecosystem coverage and later disclosures remain possible. Next review: before beta or within 14 days, whichever comes first.
